# jobs — 分 Phase 工作項

> 上游文件：`RPD.md`（需求）、`MVP.md`（MVP 範圍）。
> 原則：每個 Phase 結束都有**獨立可用的產出**，可隨時停在任一 Phase 而不爛尾。
> 工作項編號 `J<phase>.<seq>`；每項含產出與完成條件（DoD）。

## 總覽

| Phase | 名稱 | 產出 | 對應 |
|-------|------|------|------|
| 0 | 資料盤點與整備 | 可信的歷史資料庫 + point-in-time 介面 | MVP |
| 1 | 特徵與規則訊號 | 每日 Top10 候選清單（手動執行） | MVP |
| 2 | 回測引擎與報告 | 3 年回測績效報告 | MVP |
| 3 | 自動化與資料擴充 | 全自動每日 pipeline + 法人籌碼訊號 v2 | 後 MVP |
| 4 | ML 排序模型 | LightGBM 排序 + walk-forward 報告 | 後 MVP |
| 5 | 監控與迭代 | live 追蹤報表、敏感度分析、滑價模型 | 持續 |

依賴：0 → 1 → 2 為串行（MVP 主線）；3 依賴 2；4 依賴 3（需法人特徵與更長資料）；5 與 4 可並行。

## Phase 0 — 資料盤點與整備

目標：把「假設可信」變成「驗證過可信」。對應 RPD §2.1 假設 A1–A5。

| Job | 內容 | DoD |
|-----|------|-----|
| J0.1 | 盤點 `tw_market_core.py`：schema、表清單、更新邏輯、Top20 是否留歷史（驗證 A1/A4/A5） | 一頁 `docs/data-inventory.md`，列出表/欄位/日期範圍/缺口 |
| J0.2 | 資料品質掃描：缺日、缺股、零值/異常值（驗證 A2/A3） | 品質報告腳本 `scripts/data_quality.py`，缺日率數字落地 |
| J0.3 | 歷史回填至 ≥ 3 年（不足處補抓；遵守 API 間隔 ≥ 3 秒） | MVP.md D1 通過 |
| J0.4 | 除權息資料抓取（TWSE/TPEX 或 FinMind）+ 還原價計算 `adjustments.py` | MVP.md D2 通過 |
| J0.5 | Top20 排行改為逐日留存（若 A4 不成立） | 排行表含日期主鍵，可查任意歷史日 |
| J0.6 | 建 `core_db.py` point-in-time 取數介面（唯一入口；`as_of` 參數強制） | 單元測試：`as_of=D` 取不到 D+1 的資料 |
| J0.7 | 專案骨架：`src/` 結構、pytest、requirements、ruff | `pytest` 綠燈跑通空測試 |

**Phase 0 產出**：一個驗證過完整性的歷史資料庫 + 取數介面。即使專案停在這裡，資料庫本身已升級。

## Phase 1 — 特徵與規則訊號 v1

目標：每日可手動產出 Top10 強勢股候選清單。刻意用簡單規則當基線。

| Job | 內容 | DoD |
|-----|------|-----|
| J1.1 | 股票池模組：上市+上櫃普通股、日均成交值 ≥ 5,000 萬過濾、以「當日存在」為準（防存活者偏差） | 單元測試含下市股情境 |
| J1.2 | 特徵計算 `momentum_volume.py`：5/20/60 日報酬、量比、波動度、成交值 Top20 進榜旗標；純函式 | 對 2–3 檔手算樣本驗證；全市場單日 < 5 分鐘 |
| J1.3 | 規則評分 `rule_v1.py`：特徵 z-score 加權合成 → Top N；權重集中成一個 config | 同輸入同輸出（確定性測試） |
| J1.4 | `predictions` 表 + `daily_run.py`：更新資料 → 算分 → 落地當日快照（股票、分數、各特徵值、版本號） | 連續 5 交易日手動執行成功（MVP.md D6） |
| J1.5 | 快照含「理由欄位」：每檔列出主要得分來源，供人工覆核 | 快照可讀，隨機抽查合理 |

**Phase 1 產出**：每天一份可人工參考的候選清單（尚未驗證績效）。

## Phase 2 — 回測引擎與報告（MVP 完成線）

目標：用數字回答「這個訊號扣完成本行不行」。

| Job | 內容 | DoD |
|-----|------|-----|
| J2.1 | vectorbt 技術評估：以玩具策略驗證能否表達「每日排名換股 + 漲停不成交 + 台股成本」；不合用則決策自寫向量化引擎 | 一頁決策記錄（採用/自寫 + 理由） |
| J2.2 | 成本與成交規則 `costs.py`：手續費 0.1425%×2（可設折扣）、證交稅 0.3%、次日開盤成交、漲停不買/跌停不賣 | MVP.md D4 通過 |
| J2.3 | 回測引擎 `engine.py`：區間、持有 H 日、Top N、等權重；**重用 Phase 1 的 features/rule_v1 同一份程式碼** | 3 年回測 < 10 分鐘 |
| J2.4 | 前視偏差測試：抽 20 個歷史日期，回測選股 == 截斷資料 live 選股 | MVP.md D3 通過（此項不過，Phase 2 不算完成） |
| J2.5 | 績效報告 `report.py`：總報酬/CAGR/Sharpe/MDD/勝率/換手率/逐年分拆，vs 0050 與加權報酬指數 | MVP.md D5 通過 |
| J2.6 | 基準資料：0050 與加權報酬指數歷史入庫 | 基準曲線與公開數據抽查相符 |
| J2.7 | 可重現性驗證：同參數重跑 byte-identical | MVP.md D7 通過 |

**Phase 2 產出 = MVP**：閉環完成。此時應停下來讀報告，決定訊號值不值得繼續投入。

## Phase 3 — 自動化與資料擴充

目標：零人工介入的每日 pipeline，並擴充籌碼面資料。

| Job | 內容 | DoD |
|-----|------|-----|
| J3.1 | cron/systemd timer 排程 `daily_run.py`（台股收盤後，建議 15:30 與 20:00 兩次，第二次補抓） | 連續 10 交易日零人工（RPD 成功指標） |
| J3.2 | 失敗處理：抓取重試退避、缺日偵測、錯誤通知（Telegram/Line/email 擇一） | 人為斷網演練：收到告警且隔日自動補齊 |
| J3.3 | 三大法人買賣超日資料入庫（TWSE T86 / TPEX 對應 API，或 FinMind） | 回填 ≥ 1 年，品質掃描通過 |
| J3.4 | 融資融券餘額入庫 | 同上 |
| J3.5 | 處置股/注意股清單入庫，股票池改用真實清單剔除 | 取代 MVP 的「連續漲停」近似 |
| J3.6 | 訊號 v2：納入法人連買日數/買超金額比等特徵，回測對照 v1 | v1 vs v2 回測對照報告 |
| J3.7 | 日報輸出：每日清單 + 昨日預測對答案摘要，推送到通知渠道 | 每日自動收到日報 |

**Phase 3 產出**：不用碰鍵盤，每天自動收到候選清單與追蹤摘要。

## Phase 4 — ML 排序模型

目標：用 LightGBM 排序取代（或輔助）規則加權，並以 walk-forward 誠實評估。
前置條件：資料 ≥ 3 年含法人特徵；Phase 2 的規則基線績效已知。

| Job | 內容 | DoD |
|-----|------|-----|
| J4.1 | 標籤設計：未來 H 日相對加權指數超額報酬（回歸或分箱排序標籤），文件化理由 | `docs/label-design.md` |
| J4.2 | 訓練資料管線：由 point-in-time 介面產生特徵矩陣，嚴防標籤洩漏 | 洩漏測試（打亂日期應使績效歸零） |
| J4.3 | LightGBM 排序模型 + walk-forward（如訓 2 年、驗 3 月、滾動前進），固定 seed | walk-forward 各期指標落地 |
| J4.4 | 模型 vs 規則 v1/v2 回測對照（同成本、同區間） | 對照報告；ML 未顯著勝出則明文記錄並停留規則版 |
| J4.5 | 每日推論整合進 pipeline，模型檔版本化（predictions 表記 model version） | 快照可追溯是哪個模型產的 |
| J4.6 | 特徵重要度與穩定性檢查（各期 top 特徵是否漂移） | 報告落地 |

**Phase 4 產出**：一份誠實的「ML 有沒有比簡單規則強」結論；強才上線，不強就留規則。

## Phase 5 — 監控與迭代（持續性）

目標：讓 live 表現持續被看見，防止回測自欺與策略衰退。

| Job | 內容 | DoD |
|-----|------|-----|
| J5.1 | live 追蹤報表：滾動 20/60 日命中率、live 累積超額報酬 vs 回測期望 | 週報自動產出 |
| J5.2 | 回測-實盤落差監控：live 績效落出回測分佈（如低於歷史滾動 5 百分位）即告警 | 告警演練通過 |
| J5.3 | 參數敏感度分析：對 N、H、過濾門檻掃描，確認績效不是單點運氣 | 敏感度熱圖報告 |
| J5.4 | 滑價模型：以成交值/委買賣估計衝擊成本，取代「開盤全額成交」假設 | 回測報告加註滑價後數字 |
| J5.5 | 季度回顧流程：檢視訊號衰退、資料品質、是否重訓/調參 | 每季一頁回顧記錄 |

## 里程碑與時間感（個人 side project 節奏，僅供參考）

| 里程碑 | 內容 | 粗估投入 |
|--------|------|----------|
| M1 | Phase 0 完成：資料可信 | 2–3 個週末 |
| M2 | Phase 1 完成：每日清單 | 1–2 個週末 |
| M3 | **Phase 2 完成：MVP，回測報告出爐** | 2–3 個週末 |
| M4 | Phase 3 完成：全自動 | 2 個週末 |
| M5 | Phase 4 完成：ML 對照結論 | 3–4 個週末 |

原則提醒：M3 是決策點——回測若顯示訊號扣成本後無 alpha，優先迭代訊號（回 Phase 1）
而不是直接跳 ML；ML 救不了沒有資訊量的特徵。
